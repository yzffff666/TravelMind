# TravelMind 导师演示小抄

## 1. 演示前启动

在项目根目录运行：

```powershell
.\scripts\start_demo.ps1
```

启动后浏览器打开：

```text
http://127.0.0.1:3000
```

如果浏览器没有自动打开，就手动打开上面的地址。

## 2. 推荐演示顺序

### 第一步：主链路生成

输入：

```text
帮我规划 3 天成都亲子游，预算中等，节奏轻松
```

可以这样讲：

```text
这里展示的是旅行规划主链路。用户输入目的地、天数、预算和偏好后，系统会完成需求理解、POI 召回、行程生成和坐标回填。
```

### 第二步：已有行程问答

输入：

```text
第 2 天安排是什么？
```

可以这样讲：

```text
这里展示的是基于已有行程的问答。这类问题可以复用当前 itinerary，不需要重新生成完整行程，所以响应会比较快。
```

### 第三步：局部编辑

输入：

```text
把第二天下午改成更轻松的室内活动
```

可以这样讲：

```text
这里展示的是多轮编辑。系统会基于已有行程做局部修改，而不是完全重新生成。
```

### 第四步：讲观测和成本控制

不用现场跑海外链路，直接讲：

```text
除了前端主链路，我最近还补了观测和成本控制。系统现在能统计 LLM、Provider、缓存、坐标回填和 POI Ranking 的表现。海外 POI 日常优先走 Geoapify，SerpAPI 作为兜底，并且有缓存和 live 调用预算，避免调试时把 API 额度用完。
```

## 3. 一分钟口径

```text
这个项目一开始是旅行规划助手，核心是根据用户需求生成行程。现在我把它往工程化方向推进了三步：第一，把主链路跑通并支持多轮问答和编辑；第二，补了观测能力，可以知道 LLM、地图接口、缓存和坐标回填哪里慢、哪里失败；第三，做了成本优化，海外 POI 日常用 Geoapify，SerpAPI 作为兜底，并加了缓存和额度保护。下一步会把真实失败样例沉淀成 badcase 数据集，用来继续优化 POI 排序质量。
```

## 4. 现场兜底话术

如果 LLM 慢：

```text
这里依赖外部 LLM，现场可能有波动。也正因为这个原因，我补了观测日志，用来区分是模型慢、Provider 慢还是本地逻辑问题。
```

如果海外 API 不稳定：

```text
海外 POI 依赖外部 Provider，现场网络和额度可能波动。所以我做了 Geoapify 低成本 Provider、SerpAPI 兜底、缓存和预算保护。现场主要演示稳定主链路，海外部分通过 smoke 和观测报告验证。
```

如果前端临时打不开：

```text
前端如果临时环境有问题，我可以直接展示后端 smoke 和观测报告。这个项目的重点不只是 UI，而是主链路、观测闭环和 Provider 成本治理。
```

## 5. 不建议现场演示

- 不建议现场跑完整海外长链路，容易受 LLM、Geoapify、SerpAPI、网络和数据库状态影响。
- 不建议现场清缓存，缓存是 demo 稳定性的朋友。
- 不建议现场临时改 `.env`，避免 key 或端口出错。
