# TravelMind 真实 Provider 评测计划

## 1. 目标

本评测用于确认 TravelMind 在真实 Provider 环境下的稳定性、点位质量与降级表现。当前主链路已经打通，下一阶段重点不是继续堆功能，而是把“真实网络 + 真实地图/搜索数据”带来的不确定性收敛到可观测、可复现、可验收。

## 2. 评测范围

本轮只覆盖与旅行规划主链路强相关的 Provider 行为：

- 首次生成行程时的搜索召回、地图 POI 召回、证据组织与坐标回填。
- 编辑行程后 changed day / changed slot 的局部坐标回填。
- 国内与海外城市的点位匹配精度、fallback 触发率和地图可渲染性。
- Provider 超时、空结果、低置信度结果时的降级说明是否可解释。

暂不覆盖：

- 大规模并发压测。
- 支付、账号、用户权限等非旅行规划链路。
- 完整生产级 APM 接入。

## 3. 核心指标

| 指标 | 含义 | 目标口径 |
|---|---|---|
| Provider P50 / P95 | 单请求 Provider 阶段耗时 | P95 不应明显拖慢最终输出 |
| 坐标回填 P50 / P95 | 缺坐标 slot 的回填耗时 | P95 在可接受等待范围内，且有超时预算 |
| fallback 触发率 | 使用城市中心或模板坐标的比例 | 越低越好，海外场景单独统计 |
| 点位可渲染率 | 行程 slot 是否能在地图上显示 marker | 核心演示用例应接近稳定可显示 |
| 跨城市/跨国家误匹配率 | POI 坐标是否明显落到错误区域 | 必须人工抽检，海外优先 |
| Provider 降级率 | 超时、空结果、异常导致降级的比例 | 需要写入 assumptions 或日志 |
| evidence 可追溯率 | slot 是否能关联来源、provider 或说明 | 无 URL 时至少保留 provider/source |

## 4. 固定评测样例

本轮至少使用以下三类样例：

- 国内标准样例：上海、北京、成都、杭州。
- 海外样例：普吉岛、东京、大阪、新加坡、巴黎、伦敦等。
- 编辑样例：把某一天某个 slot 替换为一个真实 POI，观察 changed day / changed slot 是否能补齐坐标。

详细样例见 `docs/fixtures/海外POI精度回归样例.md`。

## 5. 执行步骤

1. 启动后端与前端，确认 `.env` 中真实 Provider key 已配置。
2. 逐条输入固定样例，记录生成是否成功、耗时、coverage、fallback 情况。
3. 对每条完整行程执行一次编辑操作，替换一个下午或晚上 slot。
4. 打开地图检查 marker 是否显示、是否落在合理区域。
5. 对失败或降级样例记录原始 query、Provider 返回摘要、最终 assumptions/conflicts。

## 6. 通过标准

本轮评测通过需要满足：

- 国内核心样例能稳定生成并显示地图 marker。
- 海外样例不再出现地图空白；若使用 fallback，必须可解释。
- 编辑后的新增 slot 至少能获得可渲染坐标，不应保留旧地点脏坐标。
- Provider 异常不应导致接口崩溃，应进入降级或 assumptions。
- 所有失败样例都能归档到失败对话库，便于后续修复。

## 8. 下一步建议

若本轮发现海外 fallback 比例偏高，优先做目的地边界框、地址国家校验和 Provider 置信度规则。若主要问题是耗时抖动，则优先补 Provider 超时预算、并发限制和失败重试策略。
