## 13. Agentic POI Ranking shadow 观测口径

项目定位已从“继续修 backfill 长尾”调整为“Agentic POI Ranking for Travel Planning”。因此后续 smoke 的重点不再只是看 unresolved 数量，而是观察 Provider 候选在进入 LLM 前是否被更合理地排序和过滤。

新增观测入口：

- `travel_draft_graph.py` 在 recall 阶段旁路运行 `POIRankingPolicy`，并记录 `poi_ranking_shadow`。
- `observability_summary.py` 汇总 `POI Ranking Shadow`，展示 accepted/rejected 数量、reject reasons、Top-K overlap 和 rejected samples。
- 当前 shadow policy 不改变主链路输出，只用于比较 legacy ranking 与新策略，避免在样本不足时误伤真实 POI。

下一轮验证建议：

1. 使用同一批 `mini` / `extended` / `bilingual` 用例跑 smoke。
2. 优先读取 `observability-summary.md` 的 `POI Ranking Shadow` 小节。
3. 如果 `top_k_overlap_rate` 很低，先人工审查 `POI Ranking Rejected Samples`，再决定是补 alias/bbox、补 CandidateFeature，还是收紧 hard gate。
4. 如果 rejected samples 多数是泛活动、bbox invalid 或 duplicate，则说明 hard gate 可能有效；如果拒掉了明确 POI，则不能直接切主路径。

结论：Backfill unresolved 仍然是有价值的质量信号，但它更适合被看作“候选排序没有提前处理好的后果”。长期方向是把错误尽量前移到 CandidateFeature / RankingPolicy 层可解释地处理，而不是一直在后处理阶段补洞。
