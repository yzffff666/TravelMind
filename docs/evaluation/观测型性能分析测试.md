# TravelMind 观测型性能分析测试

## 1. 目标

本测试用于验证真实业务链路下的阶段耗时、缓存命中、Provider 状态、QP fallback 和坐标回填质量。它不是并发压测，而是小样例真实链路观测。

## 2. 前置条件

先启动后端，并确认 `.env` 中的 LLM、Provider、Redis、MySQL 配置可用：

```powershell
cd llm_backend
py -X utf8 run.py
```

后端启动后会写入：

- `logs/app.log`：人类可读文本日志。
- `logs/structured.log`：JSON 结构化日志，推荐用于指标汇总。

## 3. 执行 smoke 用例

默认 `mini` 用例集覆盖：

- 缺字段澄清。
- 国内完整规划。
- 基于同一 conversation 的编辑。
- 基于同一 conversation 的 QA。

执行命令：

```powershell
cd llm_backend
py -X utf8 -m scripts.observability_smoke --base-url http://127.0.0.1:8000 --user-id 1 --case-set mini
```

如需加入海外样例：

```powershell
py -X utf8 -m scripts.observability_smoke --base-url http://127.0.0.1:8000 --user-id 1 --case-set extended
```

默认请求路径是 `/api/travel/query`。如果后端以无 `/api` 前缀方式挂载，可以显式指定：

```powershell
py -X utf8 -m scripts.observability_smoke --query-path /travel/query
```

输出目录默认为：

```text
llm_backend/reports/observability-runs/<timestamp>/
```

主要产物：

- `smoke-report.md`：每个用例的 HTTP/SSE 结果摘要。
- `smoke-results.json`：机器可读运行结果。
- `*.events.jsonl`：每个用例的 SSE 事件明细。
- `observability-summary.md`：如果存在 `logs/structured.log`，自动生成阶段级观测汇总。

## 4. 单独生成日志汇总

如果已经有一段运行日志，可以不跑 smoke，直接生成汇总报告：

```powershell
cd llm_backend
py -X utf8 -m scripts.observability_summary --log logs/structured.log --output reports/observability-summary.md
```

也可以输出 JSON：

```powershell
py -X utf8 -m scripts.observability_summary --log logs/structured.log --format json --output reports/observability-summary.json
```

## 5. 结果解读

优先看这些指标：

- LLM：`status_counts`、`retryable_failures`、`latency_ms.p95`。
- Cache：`source_counts`、`hit_rate`、`lookup_ms.p95`、`max_scanned_count`。
- Provider：按 `provider_name:provider_kind` 分组的 `status_counts`、`error_counts`、`elapsed_ms.p95`。
- Backfill：`filled / attempted`、`fallback_reasons`、`bbox_invalid_count`。
- QP：`source_counts`、`fallback_reasons`、`confidence`。

判断方向：

- LLM P95 高或 retry 多：优先做 prompt 压缩、分阶段生成或 LLM 输出缓存。
- Cache miss 高：检查缓存 key、相似阈值、query 归一化和热点样例。
- Provider 慢或 timeout 多：补 Provider 结果缓存、长尾 POI 样例和 fallback 策略。
- QP fallback 多：扩充 Structured QP 评测集并分析低置信度样例。

## 6. 注意事项

- `mini` 也会触发真实 LLM 和 Provider 调用，耗时可能达到数十秒。
- 本测试关注链路观测，不代表系统并发极限。
- 并发压测应单独设计，避免误把外部 LLM / Provider 波动当成本服务吞吐瓶颈。
